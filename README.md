C言語ゼロ・周辺知識ゼロの状態から、**自分の手でプログラムの実行フローを乗っ取る**（スタックバッファオーバーフロー）までを、一歩ずつ体験した記録。

アメリカのCS学科で定番の実習（CMU "Attack Lab" / Aleph One "Smashing the Stack for Fun and Profit" 系）の、最も基本の型「ret2win」をゴールにしている。

## 最終的に達成したこと

本来どこからも呼ばれない `win()` 関数を、長すぎる入力だけで動かした。

```
*** 乗っ取り成功！本来呼ばれないwin()が動いた ***
```

## つかんだ一番大事な考え方

- メモリは「**番地のついた箱が一列に並んだもの**」。
- 関数を呼ぶと使い捨ての作業スペース（**スタックフレーム**）ができ、その中に
  入力を入れる箱（**buffer**）と、終わったらどこへ戻るかを書いた**戻り先メモ**が**隣り合って**並ぶ。
- buffer に収まる量を超えて書き込むと、あふれた分が隣の**戻り先メモを上書き**する。
- 戻り先メモを「ゴミ」ではなく「**行かせたい関数の本物の住所**」で上書きすると、CPUはそこへジャンプする。これが乗っ取り。

## 環境

## 重要：学習用に「防御を外している」

このリポジトリのビルドでは、現代のコンパイラが既定でONにしている防御を**わざと切っている**。

| フラグ | 意味 | 外している防御 |
|--------|------|----------------|
| `-fno-stack-protector` | スタックカナリアを無効化 | buffer と戻り先メモの間に置く「見張り値」 |
| `-no-pie` | 住所を固定 | （PIE：実行ファイルの配置ランダム化） |
| `setarch -R` | 実行時ASLR無効化 | 番地ランダム化（今回は使わず済んだ） |

→ **現実のソフトはこれらが全部ONなので、同じ攻撃はそう簡単には通らない。**
   「なぜ現代は乗っ取りにくいか」は step5 の最後で体験する。

## 安全・倫理について

ここでやっているのは、**自分の管理下にある学習用VMの中だけ**で、自分で書いた脆弱なプログラムを攻撃する行為。
他人のシステムに対して許可なく行えば犯罪になる。あくまで「攻撃のしくみを理解して、守る側になる」ための学習。
